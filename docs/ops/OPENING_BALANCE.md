# الرصيد الافتتاحي على السيرفر (قبل تفعيل المزامنة)

**ليه؟** السيرفر بيرفض يبيع صنف رصيده عنده صفر. لو الرصيد الافتتاحي مش مسجّل، الفواتير بتفضل «فواتير تنتظر رصيد الصنف على الخادم» لحد ما الرصيد يوصل، والسيرفر ما بيسمحش بمخزون سالب (قاعدة مالية، تغييرها قرار المالك).

## الخطوات
1. جهّز ملف `products.csv` بالأعمدة: `code,qty,cost,lot,expiry,name`
   - `code`: الباركود (نفس الكود اللي بيتباع بيه).
   - `qty`: **أصغر وحدة** (قرص للأصناف اللي ليها تعبئة، وإلا علبة). رقم صحيح أكبر من صفر.
   - `cost`: تكلفة الوحدة بالجنيه. `lot` و`expiry` (YYYY-MM-DD) اختياريين.
2. **تجربة جافة** (مفيش أي إرسال؛ بيطبع أعداد وأي صف فيه مشكلة):
   ```
   node tools/backend/opening-balance.mjs products.csv
   ```
3. صلّح الصفوف المرفوضة، وبعدين الإرسال (المالك فقط، التوكن من البيئة ومش بيتطبع):
   ```
   $env:NOVA_URL='https://<عنوان الباك إند>'; $env:NOVA_TOKEN='<توكن جلسة المالك>'; node tools/backend/opening-balance.mjs products.csv --push
   ```
4. إعادة التشغيل آمنة: المفاتيح ثابتة (`open:<code>:<lot>`) فمفيش رصيد بيتضاف مرتين.

## بعد الاستيراد
الفواتير اللي كانت منتظرة بتتبعت لوحدها في المزامنة الجاية. فعّل المزامنة على جهاز واحد الأول وراجع إن رصيد الصنف على الجهاز = رصيد السيرفر قبل ما توسّع.

الاختبار: `tests/unit/opening-balance.check.mjs`. المحاكاة: `tests/sim/pharmacy-day.sim.mjs` (الأوضاع `SIM_OPEN` و`SIM_CROSS` و`SIM_LATE` و`SIM_TOKEN`).
