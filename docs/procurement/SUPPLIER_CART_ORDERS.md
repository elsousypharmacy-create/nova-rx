# BUY-04 / BUY-05 — سلال الموردين وتنفيذ الطلب

نطاق الحساب: حساب الصيدلية المربوط لكل مورد. هذه بوابة تكامل للموردين، وليست ترحيلًا لقاعدة ERP أو دفتر المخزون/المال.

## الاستخدام

1. اختَر الموردين ومخازن أوميت من إعدادات المشتريات. اختيار العرض/التوزيع يجهز قائمة محلية؛ حفظها لا يكتب سلة المورد.
2. «مراجعة قائمة التجهيز» ثم «مراجعة سلال الموردين وتجهيز الإضافة» يعرض الموجود + المطلوب = المستهدف. التأكيد يكتب السلة ويقرأ الكمية عند المورد؛ علامة «في سلة المورد» لا تظهر قبل التحقق.
3. زر المورد في شاشة البيع أصبح إضافة فعلية مؤكدة، ولا يكتب «تمت الإضافة» لمجرد حفظ localStorage. العروض غير المؤهلة لا تُضاف.
4. «سلال الموردين» يقرأ سلة الحساب الفعلية، بما فيها أي أصناف أُضيفت خارج نوفا. «مراجعة طلب…» يعرض كل الأصناف المختارة والكميات والإجمالي والدفع والتوصيل. افحص الكل، ووافق صراحة؛ أوفرسيز يتطلب الموافقة على شروطه أيضًا.
5. التنفيذ يتبع عقد الموقع الفعلي ويحتاج رقم طلب وقراءة الطلب من المورد. لا يُعدّ HTTP 200 وحده نجاحًا. أوامر كل مورد مستقلة؛ قد ينجح أحدهما ويفشل الآخر.

## العقود والأدلة

- جلسات الموردين محفوظة مشفرة في Worker، وPIN على جميع المسارات. المتصفح لا يستقبل كلمات مرور أو توكنات الموردين.
- Aumet: رصد POST `/api/v2/cart/{cart}/items` مع absolute quantity في 42703168722، وإيقاف الكتابة قبل وصولها. GET `/api/cart/{cart}/products-quantities` للتحقق. قراءة تفاصيل GET `/api/v2/cart/{cart}/items` نجحت في 42717791769.
- PO: قراءة GET `/occ/v2/pharma/users/current/carts` نجحت. المصدر `chunk-7A7ZXZ46.js` في artifact13719466872 / run42718480038: active cart هو أول cart بدون saveTime؛ لا استخدام للسلال المحفوظة. إنشاء السلة POST users/current/carts. الإضافة المخصصة POST orgUsers/current/carts/{cart}/entries مع quantity وcode في query وform content type؛ تعديل الموجود PATCH users/current/carts/{cart}/entries/{entry} بالكمية المطلقة.
- Aumet checkout: public `app-DwBKkwMO.js`، artifact13718923970 / run42719118982: POST `/api/v2/order` بحقل entity_id ومجموعات sellers. CheckoutCartPage يقرأ response.data[] ويعرض id؛ القراءة اللاحقة `/api/v2/order/{id}` مطلوبة.
- PO checkout: `chunk-72IZRT3W.js` والمخصص في main-XHSVVZX4.js: POST orgUsers/current/orders، fields=FULL وcartId وtermsChecked في query، form content type؛ القراءة users/current/orders/{code}?fields=FULL.
- جميع العقود من كود الموقع العام أو طلب قراءة حقيقي؛ لا استنتاج لعقد كتابة من أسماء متوقعة. لم يُستخدم التقاط طلب شراء حقيقي.

## منع التكرار والنتائج غير المحسومة

- سطر السلة له خطة موقعة لمدة15 دقيقة، مع مراجعة جديدة للسعر/الدفع/المتاح قبل الكتابة. خطة الشراء120 ثانية، تربط بصمة السلة الفعلية والدفع والعنوان والإجمالي.
- `NOVA_PURCHASE_OPS` قاعدة D1 منفصلة `nova-procurement-ops`. migration0001 تنشئ supplier_operations ومؤشرًا فريدًا على المورد للعمليات pending/unknown. الجلسات والأسرار ليست في الجدول.
- claim ذري قبل أي mutation، مع receipt محفوظ. نفس العملية يعيد النتيجة عبر أجهزة/Worker isolates؛ عملية غير محسومة تمنع mutation جديدة لنفس المورد. إعادة فتح الصفحة تستخدم الخطة الأصلية وstatus فقط.
- انقطاع الرد لا يعيد POST. إضافات السلة تُسوّى بقراءة المستهدف، والطلبات ذات IDs تُسوّى بقراءة IDs. إذا لم يصل ID أصلًا فلا نخمن النجاح أو نعيد الشراء. تبقى unknown لحين مراجعة حساب المورد وتسوية موثقة؛ لا تُحذف/تنتهي الأقفال تلقائيًا ولا تُغيّر الحالة يدويًا بلا دليل.
- الطلبات غير المحسومة تعرض أي IDs مستلمة. السلة لا تتزامن عكسيًا إلى مخزون الصيدلية؛ الاستلام والفاتورة المخزنية مسار لاحق.

## التحقق

اختبارات unit ببيانات مصطنعة تغطي تغير السعر، السلال المحفوظة، الإنشاء بعد الموافقة، PATCH المطلق، double click، replay عبر instances، قفل unknown، terms، تغير السلة، IDs وread-back. SQLite حقيقي لاختبار القيود. Playwright لاختبار مراجعة/تأكيد/refresh/status على1280×800 و390×844. فحص حي منفصل `Supplier cart read check` يقرأ فقط.

الإضافة الحقيقية والشراء لأول قائمة يحتاجان تجربة المالك بأصناف مطلوبة فعلًا. اختبارات fixtures وقراءة السلة ونشر الكود لا تُثبت تنفيذ طلب شراء حي. لا ترفع BUY إلى verified لهذا السبب وحده.
